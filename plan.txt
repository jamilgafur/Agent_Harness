## 3. Architecture (all docker, all local)

One image (`Dockerfile`, python:3.12-slim, tagged `harness:latest` — the explicit
`image:` key is load-bearing: without it compose builds three stale per-service
images and `docker build` updates nothing), three core services + volumes:

```
compose.yaml
├── core     uvicorn harness.core:app :8000   (host :${PORT:-8000})
│            FastAPI: DAG store + validation, approvals, checkpointing (SQLite /data),
│            exec mediator to sandbox, tool registry, WebSocket /ws, serves UI statics
├── agent    python -m harness.agent          (replicas: 1, scale with --scale)
│            Loop: claim node → exec via core (approval-gated) → judge → report,
│            or decompose node via LLM → validate → apply
├── sandbox  uvicorn harness.sandbox:app :8001 (internal only)
│            Shared exec: shell + file ops in /workspace volume. ONLY place code runs.
└── ui       static SPA served by core at /   (no separate container)

profiles:
└── local-ollama (opt-in: docker compose --profile local-ollama up)
    ├── ollama       ollama/ollama + nvidia reservation, OLLAMA_NUM_CTX=4096,
    │                internal-only (host :11434 belongs to the aistack relay)
    └── ollama-pull  one-shot: pulls $MODEL after ollama is healthy

volumes: data (SQLite checkpoints), workspace (shared scratch), ollama_models
Deployment: lives in ~/Docker_Enviorment/harness (auto-discovered by start_all.sh);
PORT=8100 + COMPOSE_PROFILES come from .env; restart policies + watchtower
opt-out labels on all services; UI at http://ubuntu:8100, listed on the homepage
under "AI & LLM Services". Run history and models survive restarts via volumes.
Ollama default is the internal service; remote GPU box via
  OLLAMA_URL=http://host.docker.internal:11434 MODEL=qwen2.5:7b docker compose up
This box: GTX 1660 Ti 6GB → MODEL default qwen2.5:3b (~1.9GB, fast, weak-but-works).
The 1070 box stays the option for 7b+. No Redis/NATS — HTTP + WS only.
```

## 4. Contracts

Core REST (all JSON):
- `POST /runs` — `{intent}` (seed root) or `{nodes:[...]}` (validated template import) → `{run_id, errors?}`
- `GET /runs` → summaries · `GET /runs/{id}` → full state (nodes, stats, policy) · `DELETE /runs/{id}` (inactive only)
- `GET /runs/{id}/events?after_id=` → persisted event/mailbox log (cap 500/run)
- `POST /claim {agent_id, max_nodes=1}` → up to 8 ready nodes, atomic; locality preference, Alg-2 visited exclusion
- `POST /runs/{id}/nodes/{nid}/result {state, result?, hint?, llm_calls?}` — settle: parents, cascades, loop requeue, governor
- `POST /runs/{id}/nodes/{nid}/decompose {children:[...]}` → validated patch or pending patch-approval
- `POST /runs/{id}/nodes/{nid}/redirect {agent_id, reason}` — handoff; records visited set
- `POST /runs/{id}/exec {node_id, tool, args}` → auto-executes if tool ∈ auto_approve else creates approval
- `GET /exec/{exec_id}` → status + result (agent polls)
- `GET /approvals?status=pending` · `POST /approvals/{id} {decision, args?}` (edit-and-resubmit)
- `GET /tools` → static + dynamic + MCP registry · `POST /tools/sync` → add/prune from sandbox discovery
- `POST /runs/{id}/patch` — graph ops (`add_node`, `add_edge`, `replace_tool`, `retry_node`) for user fixes
- `GET /policy` · `POST /policy` — runtime: max_agents, approve_dag_edits, claim_lease_seconds, confirm_actions, auto_approve
- `GET /autosize` → ollama ping → suggested max_agents (latency bands)
- `GET /metrics` → per-run + totals: latency, TSR, FRT, delegation depth, first-pass (KG-consistency proxy)
- `GET /workspace/files|file` → read-only proxy to sandbox (UI files panel)
- `GET /health` → core ok + ollama reachable · `WS /ws` → state/approval/log/agents/policy events

Loop semantics: node `{type: loop, tool, condition, max_iterations}` — agent executes the tool body,
judges `condition`; unmet → requeue PENDING (hint + result kept), met → DONE, `max_iterations` spent →
ESCALATED + descendants BLOCKED (the infinite-loop fallback).

Budget governor: `max_llm_calls`/`max_seconds` checked on claim sweep, on every result report, and before
decompose → breach terminates the run (live nodes → ESCALATED w/ `budget governor: …`, finished work kept).

Execution semantics:
- Tool node: executor fills nothing; node carries tool+args from decomposition. No `success_predicate` → shell success = rc==0 (no LLM call → offline-testable). With predicate → LLM judge `{ok, why}`.
- Abstract node (no tool): executor decomposes. Children get ids `{parent}.{i}`, `parent` field set, depth = parent.depth+1, deps = parent.deps ∪ chosen siblings. Parent → WAITING; all children DONE → parent DONE (result = child results map); child terminally fails → parent same state.
- Failure: REPAIRING while attempts ≤ policy.max_repairs (hint fed to next claim); then ESCALATED (hint to user) + descendants BLOCKED (`graph.descendants`). User fixes via UI → `retry_node` op → recompute un-BLOCKED.
- Augmented validation: `apply_patch` requires terminal nodes (except tool nodes with auto_approve... simpler: auto_approve tools exempt) to carry a `success_predicate` — forces LLM to think in outcomes, judge never defaults to "ask LLM".

Sandbox endpoints: `POST /shell {cmd, timeout}`, `/read_file`, `/write_file`, `/list_dir` — paths confined to /workspace, output truncated 20KB, timeout ≤60s. `/web_search` reads the top 3 pages itself (`page_text` per hit via `_page_text`) — snippets alone weren't research; `_material` prefers page_text over snippets. `_force_synthesis` also grounds lone llm children (single bare writer → search+sink). UI is human-facing: state-pill detail card + readable approval cards w/ collapsible JSON, prose output modal, clickable attention chip; tab delete moved out of nested button (click bug); hard-refresh required after rebuilds.

Agent loop: claim → tool ? exec+w poll+judge : decompose (LLM, ≤max_repairs resubmits) → report. Heartbeat = claim poll. Budget stats counted in core per run (llm_calls reported by agent). Virtual `llm` tool = agent-side synthesis, written as a **train of thought**: a writer reads ONLY its direct deps (`_material`), and aggregate parent results prefer children's `text` summaries — leaves hold raw results, each level condenses its neighbors, head reads branch summaries. Planners still walk `_upstream` for context (600-char clip/dep). Decompose output is shape-pinned deterministically: `_force_synthesis` (research plans converge on ONE llm sink; degenerate all-gather prefix chains flattened to parallel; all-llm plans grounded into searches+sink; single llm over abstract branches becomes the sink) + `_deepen_branches` (root-level research plans become real trees: flat gather branches turn abstract and re-decompose into their own searches+summary — root.N.M ids). Acceptance is deterministic `_llm_ok` (predicates advisory — LLM-judging prose escalated runs falsely). Worker identity = `agent-<hostname-suffix>` → `docker compose up -d --scale agent=N` executes N ready leaves truly in parallel (atomic claims; max_agents default 4). Defaults ship Claude-Code-style (`harness.toml`): `approve_dag_edits=false` + `auto_approve=[web_search,http_fetch,read_file,list_dir,llm]`. Deletion: `DELETE /runs/{id}` (409 while active) / `?force=1` (terminate then remove); tabs ✕ on every run (unclipped: `.tlabel` ellipsizes, `.tdel` flex-shrink:0). **Verified live E2E, zero clicks, 3 agents**: "write a research paper on LLM quantization" → 15-node 3-level tree (3 abstract branches × searches+summary each + root sink, 1629-char grounded paper, root.4 deps==all branches); 3 agents visibly on root.1.2/root.2.2/root.2.3 simultaneously. Read-all-links round: `web_search` fetches every hit concurrently (`page_text`, ThreadPoolExecutor(6)); gather acceptance is deterministic (`judge` never LLM-judges web payloads — page_text made them too big for 3b judging, false-escalated 2/3 branches); every writer appends `_sources` URL footer (mined from raw hits AND climbing branch prose). "tell me about RAG" → 13-node tree all DONE, 30/30 pages read, Sources footer on every writer incl. head. UI end-user pass: output modal (download .md / copy / ⟳ run again), agents+events in collapsible 🛠 developer section, system-ui type outside data areas. **Plan-first checkpoint:** intent runs are plan-decoupled from execution — `phase=planning` holds tool nodes while abstract nodes decompose to atomic leaves (template DAGs skip the checkpoint); plan bar offers constraints (ride planner+synthesis prompts), ＋add-a-branch (LLM decomposes user nodes from neighbor context: parent+siblings+run goal in the claim payload), ✎edit-intent (PATCH), ✏️break-down-further (`/replan`); `/go` starts bottom-up execution. Head owns the answer: `_settle` lifts the sink writer's text into the parent (`from=`); user-added nodes re-pin the parent's sink deps (convergence invariant). Guards: tool deps on abstract children stripped during planning (result-gated planning waits for /go, never blocks `plan_ready`); Store persists phase+constraints (ALTER-migration on open). Layout: fixpoint pushes sinks one column past their inputs (0 backward edges on live graphs), fan-in arrivals spread over the card edge. **Verified live**: "tell me about paged attention" → 14-node plan, 0 execs at checkpoint → user adds "compare vLLM vs SGLang RadixAttention" branch (19 nodes, root.4 deps re-pinned to include root.5 live) → /go → 19/19 DONE → 3087-char head answer at root (`from root.4`), 12-url Sources footer, vLLM content present. 71 tests.

## 7. Decisions & risks

- One image / three commands — no build duplication.
- Approvals gate execs only; DAG patches are validated, not approved (patches are internal reasoning; user edits DAG via UI anyway). Stated to resolve #13 pragmatics.
- Terminal-node predicate requirement is skipped for auto_approve tools (keeps unattended runs unaided).
- Sandbox is a convenience boundary, not security isolation (docker-exec level). Fine for research, NOT for untrusted tools.
- Small-model JSON reliability is the #1 failure mode → all LLM output goes through `chat_json` repair + `apply_patch` validation.
- LLM-call accounting undercounts by 1 per abstract decomposition (the approval-gated decompose path returns before any report carries the delta). Not user-visible; still open post-P5 — fix by billing claims instead of reports.
- Claim lease (120s) can hand a node out twice if an agent is alive-but-slow (long LLM call mid-node); the stale-report 409 makes the loser harmless. UI: port is host-exposed unless you set PORT; auth is out of scope behind localhost.
- requirements.txt unpinned (research velocity); pin before publishing.
- `.venv/` is broken and now unused — remove when convenient.
